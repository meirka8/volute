# Volute CVC v0.7.2

Volute CVC v0.7.2 is v0.7.1 published again, with **no code change**, because the v0.7.1 release run did not publish two channels: the VS Code Marketplace, whose listing goes from 0.7.0 straight to 0.7.2, and the npm name `@volute_cvc/cvc`. What v0.7.1 added and fixed is in the [v0.7.1 release notes](https://github.com/meirka8/volute/releases/tag/v0.7.1); its upgrade steps and security fixes are repeated below.

CVC keeps **explicitly available AI-assisted development context** alongside Git history. It records only information exposed or supplied by its integrations; it neither retrieves hidden chain-of-thought nor promises a verbatim record of a black-box model's internal reasoning.

[Full Changelog](https://github.com/meirka8/volute/compare/v0.7.1...v0.7.2)

> **Action required after upgrading.** Capture acknowledgements recorded by v0.7.0 or earlier no longer count, so passive capture stays off until you grant it again. In every repository where you want the VS Code extension, the Claude Code hooks, or the Claude Code plugin to record, run `cvc privacy acknowledge-capture` once; if you set up per-checkout Claude Code hooks with v0.7.0, then run `cvc harness install claude-code` again there. Most typed consent phrases also changed and now end in a short code that the prompt shows. Upgrade the CLI, the npm launcher, the VS Code extension, and the plugin together, and do not run v0.7.0 side by side with v0.7.1 or v0.7.2 on one repository. These are the v0.7.1 steps, unchanged: if you already run v0.7.1 everywhere, v0.7.2 needs none of them. Everything to check is under Upgrade notes.

## Highlights

### No code change

- **Every component is the v0.7.1 code.** The `cvc`, `cvc-mcp`, and `cvc-lsp` binaries, the VS Code extension, the npm launcher, the Claude Code plugin, and the Reviewer behave exactly as in v0.7.1; the components that carry a version now say 0.7.2. If you are coming from v0.7.0, as VS Code Marketplace users are, what changes for you is what v0.7.1 changed, described in the [v0.7.1 release notes](https://github.com/meirka8/volute/releases/tag/v0.7.1).

### Install channels and release engineering

- **The VS Code Marketplace gets 0.7.2 instead of 0.7.1.** The v0.7.1 release run could not publish there because the Personal Access Token it used had expired, so the listing never received 0.7.1. It goes from 0.7.0 to 0.7.2 for all four targets (`darwin-arm64`, `darwin-x64`, `linux-x64`, `win32-x64`), and 0.7.2 is the first Marketplace version with the fixes for the nine security advisories listed under Release security and hardening.
- **The npm name `@volute_cvc/cvc` was not published with v0.7.1.** Its npm Trusted Publisher had not been configured when the v0.7.1 release ran. It has since been published at 0.7.1. Both npm names are published at 0.7.2.
- **The extension is published with Visual Studio Marketplace Trusted Publishing.** The release workflow authenticates to the Marketplace through OpenID Connect from GitHub Actions and receives a short-lived credential, so it stores no Marketplace token that can expire ([#180](https://github.com/meirka8/volute/issues/180), [#181](https://github.com/meirka8/volute/pull/181)). That needs `@vscode/vsce` 4.0.0 or later, so the tool that packages the extension moves from 3.9.2 to 4.1.0, and the packaged extension was verified to contain the same files.

## Included components

- `cvc-core` — Rust library for local storage, Git integration, policy enforcement, linking, sync data structures, and the Claude Code transcript adapter.
- `cvc-cli` — the `cvc` command-line interface, including `cvc conversations`, `cvc harness`, and `cvc ingest`.
- `cvc-mcp` — MCP server for explicitly submitted interaction records and local history access.
- `cvc-lsp` — language server used by editor integrations.
- `cvc-plugin` — VS Code extension for the supported local VS Code chat-session workflow.
- `plugins/claude-code` — the `cvc` Claude Code plugin (`cvc@volute`), distributed from the `volute` plugin marketplace in `.claude-plugin/`; it installs the Claude Code capture hooks.
- `cvc-reviewer` — client-side React reviewer for GitHub-hosted CVC data.
- `@volute_cvc/cvc` and `@volute_cvc/cvc-mcp` — npm launcher for released CVC binaries, published under both names (`cvc`, `cvc-mcp`, and `cvc-lsp`).

## Install

### GitHub release assets

Once the full release workflow completes, download an archive and `SHA256SUMS.txt` from the [v0.7.2 GitHub release](https://github.com/meirka8/volute/releases/tag/v0.7.2). Verify the archive against that manifest **before** extracting it, then put `cvc` (or `cvc.exe`) on `PATH`. Each archive includes `cvc`, `cvc-mcp`, and `cvc-lsp`.

| Platform | Archive |
| --- | --- |
| Linux x86-64 | `cvc-x86_64-unknown-linux-gnu.tar.gz` |
| macOS x86-64 | `cvc-x86_64-apple-darwin.tar.gz` |
| macOS ARM64 | `cvc-aarch64-apple-darwin.tar.gz` |
| Windows x86-64 | `cvc-x86_64-pc-windows-msvc.zip` |

Expected additional release assets are `LICENSE`, `THIRD-PARTY-NOTICES.md`, `install.sh`, and `install.ps1`. Each native archive and VSIX also includes the mechanically generated third-party notice file. The standalone installer assets default to v0.7.2, select the matching supported archive, and verify its checksum; set `CVC_RELEASE_VERSION` to an explicit valid release tag to override that version. Review a script before running it.

From any Git working tree, get started with:

```bash
cvc init
cvc status
cvc conversations
```

### Capture Claude Code sessions

With `cvc` installed, from the checkout you work in:

1. `cvc init` — create the local cache and the advisory Git hooks.
2. `cvc privacy acknowledge-capture` — the one-time local capture acknowledgement, an interactive typed challenge (type the phrase the prompt shows); passive capture stays off until it is granted.
3. Put the capture hooks in place, by one of:
   - `cvc harness install claude-code` — write them into this checkout's `.claude/settings.local.json` and, while the acknowledgement stands, into worktrees you create later.
   - The Claude Code plugin, once per machine — in Claude Code, `/plugin marketplace add meirka8/volute`, then `/plugin install cvc@volute`. It needs `cvc` 0.7.1 or later in an absolute directory on the `PATH` Claude Code sees (`~/.cvc/bin` by default).
4. Start a *new* Claude Code session; a session already running does not pick up the hooks.
5. Work as usual, then `cvc conversations` to see the captured sessions and `cvc log` for detail.

### VS Code Marketplace

After the full release workflow completes, [Volute CVC (`volute.cvc`)](https://marketplace.visualstudio.com/items?itemName=volute.cvc) is expected to be available from the VS Code Marketplace at 0.7.2 for `darwin-arm64`, `darwin-x64`, `linux-x64`, and `win32-x64`. The Marketplace has no 0.7.1: 0.7.2 follows 0.7.0 there. The extension supports VS Code `^1.91.0` and uses the platform-specific bundled language server. On a machine without the CLI it prompts to install it; after installing, run **Volute: Check Setup**.

### npm launcher

After the full release workflow completes, the launcher is expected to be available from npm as [`@volute_cvc/cvc`](https://www.npmjs.com/package/@volute_cvc/cvc), the name for CLI users, and as [`@volute_cvc/cvc-mcp`](https://www.npmjs.com/package/@volute_cvc/cvc-mcp), which existing MCP configurations use:

```bash
npm install --global @volute_cvc/cvc@0.7.2
```

Both provide `cvc-mcp`, `cvc`, and `cvc-lsp`, download the matching release binary on first use, verify it against the release checksum manifest, and keep the verified binaries in `~/.cvc/bin`. Install one of the two globally, not both: if `@volute_cvc/cvc-mcp` is already installed globally, run `npm uninstall --global @volute_cvc/cvc-mcp` first, or npm stops with `EEXIST`. Configure `cvc-mcp` in your MCP client as documented in the [MCP setup guide](https://github.com/meirka8/volute/blob/v0.7.2/cvc-mcp/README.md).

## Upgrade notes

- **From v0.7.1: no action.** v0.7.2 has v0.7.1's code, so behavior, consent state, local storage, and formats are unchanged, and `cvc --version` now reports 0.7.2. The notes below are the v0.7.1 upgrade notes; they apply when you come from v0.7.0 or earlier.
- **VS Code: update the extension to 0.7.2.** The Marketplace has no 0.7.1, so an extension installed from it is still 0.7.0. If you installed `cvc` 0.7.1 from a GitHub release or npm in the meantime, that is a v0.7.0 and a v0.7.1 component on one repository, which the notes below say not to do. Update the extension, then follow the notes below that apply when you come from v0.7.0.
- **Acknowledge capture again, once per repository.** The capture acknowledgement is now bound to the checkout path and the user, so acknowledgements recorded by v0.7.0 or earlier no longer count, and `cvc privacy status` says so ("capture was acknowledged for another checkout or user, or by an older cvc; run `cvc privacy acknowledge-capture` here"). Until you grant it again, passive capture (the VS Code extension, the Claude Code hooks, and the plugin) records nothing, and the Claude Code hooks report `consent-required`. In each repository where you want capture, run `cvc privacy acknowledge-capture` once. Then, for per-checkout hooks you set up with v0.7.0, run `cvc harness install claude-code` again in each checkout and linked worktree where you set them up: it needs the acknowledgement, moves hooks that point into the npm launcher's versioned cache (`mcp-cache`) to `~/.cvc/bin/cvc`, and turns on hook propagation to new worktrees.
- **No database migration and no wire-format change; upgrade every installation together.** `refs/cvc/main` stays format 5, and v0.7.0 readers still read it. Two parts of the local consent state gain meaning. `privacy.json` gets a `capture_acknowledged_binding` field, which v0.7.0 binaries ignore and v0.7.1 and v0.7.2 expect: a file without it counts as not acknowledged. And for a remote whose push URL embeds credentials (below), v0.7.1 and v0.7.2 move consent and publication records to the new fingerprint once, after which a v0.7.0 binary on the same repository no longer finds them. Do not run v0.7.0 side by side with v0.7.1 or v0.7.2 on one repository: upgrade the CLI, the npm launcher, the VS Code extension, and the Claude Code plugin together.
- **Typed phrases have new forms.** Phrases that could be worked out in advance now end in a five-character code that the prompt shows and changes every time (`<nonce>` below). Type what the prompt displays, at an interactive terminal as before:
  - `I UNDERSTAND LOCAL CAPTURE <nonce>`
  - `I AUTHORIZE SHARING <fingerprint> <nonce>`
  - `I AUTHORIZE AUTO PUSH ON|OFF <fingerprint> <nonce>`
  - `I UNSHARE <conversation-id> <fingerprint> <nonce>`
  - `I REDACT <interaction-id> <fingerprint> <nonce>`
  - `I AUTHORIZE RANGE <base> <tip> <fingerprint> <nonce>`
  - `I SHARE FUTURE <conversation-id> <fingerprint> <count> <token>`, the phrase for a future share
  - Unchanged: `I SHARE <conversation-id> <fingerprint> <count> <token>` (a snapshot) and `I PUBLISH <fingerprint> <candidate> <count>`
- **CLI output changed.** Counts say `thought(s)` everywhere (`Pulled N thought(s) from …`, `Published N new shared thought(s) …`), so scripts that match the old `interaction(s)` or `turn(s)` text need updating. `cvc conversations` opens an interactive view in a terminal; in a pipe or without a terminal it prints the plain listing as before, and scripts, and any tool that drives `cvc` through a pseudo-terminal, should pass `--plain`.
- **MCP: thoughts stay private until shared; restart running servers.** Thoughts recorded through `commit_thought` stay private until the conversation is shared again with `cvc share`; they no longer take on a conversation's future sharing or change its title. When a conversation holds MCP thoughts, `cvc share --future` says so ("Future sharing does not extend to thoughts recorded through MCP: later ones stay private until this conversation is shared again."); future sharing covers passive captures only. An MCP host keeps its server process for the session, so restart the host or the session after installing. With the npm launcher, the new release reaches `~/.cvc/bin` the next time the launcher runs ([launcher README](https://github.com/meirka8/volute/blob/v0.7.2/npm/cvc-mcp/README.md#upgrading)).
- **Remotes whose push URL embeds credentials.** The destination fingerprint is now computed over the push URL without its user information. Fingerprints of ordinary remotes are unchanged. For a remote whose push URL embeds credentials, the first command moves its consent and publication records once to the new fingerprint, and redaction plans written before the upgrade for that remote must be regenerated.
- **Installers add a `share/cvc` directory** next to the bin directory (`~/.cvc/share/cvc` by default), holding `LICENSE` and `THIRD-PARTY-NOTICES.md`.
- **The Claude Code plugin is new since v0.7.0 and ships from this tag.** The `volute` marketplace entry for `cvc` pins the plugin's files to `v0.7.2`, so plugin changes arrive only with CVC releases. Its files are the v0.7.1 files; only the version number changes. Claude Code does not auto-update third-party marketplaces by default; update with `/plugin marketplace update volute`.
- **Reviewer: no action needed.** The hosted deployment keeps its URL, local PAT mode stays the default, and search text never goes in the address.

## Privacy and sharing

CVC is **local-first, not local-only**. Captures live under the repository's common Git directory in `cvc/` and are private by default; linked worktrees share that private store. Remote publication is a separate, explicit action behind per-destination consent and an interactive challenge. Privacy.md's "How your data moves" section describes the full lifecycle in plain language.

The interactive `cvc conversations` view adds no consent path: sharing, unsharing, publishing, and authorizing a destination each still end in a typed phrase that you enter at the prompt. The challenges are a confirmation step, not a security boundary: a program that drives a terminal as you can still type a phrase. Installing the Claude Code plugin changes no consent state, but its hooks run in every Claude Code session you start. A session is recorded only in the CVC-initialized repository it was started in, and only where capture is acknowledged. There it is recorded in full, including work in other directories, under that repository's `.thoughtignore` alone ([#152](https://github.com/meirka8/volute/issues/152)); where capture is already acknowledged, recording starts with the next session and no new prompt.

A Claude Code transcript contains everything the session saw: prompts, tool output, and file contents the agent read. Review a conversation with `cvc conversations` and `cvc log` before sharing it. Built-in scrubbing and `.thoughtignore` are defense in depth, not a guarantee, and the additional forms the scrubber has recognized since v0.7.1 do not change that. Once published to Git, content may remain in objects, clones, forks, reflogs, caches, and backups. Rotate an exposed credential first; local deletion and tombstones are suppression mechanisms, not guaranteed physical erasure.

## Release security and hardening

The nine security advisories below were fixed in v0.7.1 and are published with v0.7.2. Each names 0.7.1 as its fixed version, and that stays correct: v0.7.2 has the same code. One has a part deferred to 0.8, as noted. Severity is in parentheses.

**VS Code extension users:** the Marketplace never carried 0.7.1, so 0.7.2 is the first Marketplace version with these fixes.

- [GHSA-m226-c3r4-phcv](https://github.com/meirka8/volute/security/advisories/GHSA-m226-c3r4-phcv) (medium): Captured fields are scrubbed in full before their size is bounded, the scrubber now recognizes incomplete private-key blocks and OpenPGP private keys, and a push re-checks the already-published thoughts this clone shares and stops, naming the node and the commands to run, when one cannot be re-verified.
- [GHSA-v374-58m6-65fr](https://github.com/meirka8/volute/security/advisories/GHSA-v374-58m6-65fr) (medium): Recorded content or pulled data can no longer stop the capture of Claude Code sessions, block pushes, or crash `cvc`: Read line ranges are bounded, key layouts are matched exactly, chains are walked without recursion, and a refused response no longer holds back later ingest.
- [GHSA-qxwm-8mgh-45gj](https://github.com/meirka8/volute/security/advisories/GHSA-qxwm-8mgh-45gj) (medium): Before connecting, transport is held to the consented destination URL; chained git `insteadOf` or `pushInsteadOf` rules, or a remote that changed since the command started, are refused with nothing sent.
- [GHSA-rx7w-2c37-vq28](https://github.com/meirka8/volute/security/advisories/GHSA-rx7w-2c37-vq28) (medium): Thoughts recorded through the MCP server never take on a conversation's future sharing and stay private until the conversation is shared again, and they no longer change an existing conversation's title.
- [GHSA-5r77-x7mg-vr64](https://github.com/meirka8/volute/security/advisories/GHSA-5r77-x7mg-vr64) (low): The capture acknowledgement is bound to the checkout path and the user, so a copied or moved repository asks again.
- [GHSA-w2fm-2w52-vg5v](https://github.com/meirka8/volute/security/advisories/GHSA-w2fm-2w52-vg5v) (low): The destination fingerprint is computed over the push URL without embedded user information; fingerprints of ordinary remotes are unchanged, records for credential-bearing URLs move once, and the part that concerns re-sharing a pulled conversation is deferred to 0.8.
- [GHSA-2qhh-pqwq-m4x2](https://github.com/meirka8/volute/security/advisories/GHSA-2qhh-pqwq-m4x2) (low): Phrases that could be computed in advance now end in a per-prompt code, and future shares type `I SHARE FUTURE …`.
- [GHSA-h48w-w3w3-cxf9](https://github.com/meirka8/volute/security/advisories/GHSA-h48w-w3w3-cxf9) (low): Captured or remote-supplied text that the CLI prints is neutralized (control and format characters become `?`), error text shows URLs without user information, and the pre-push hook no longer stores a URL push's user information locally.
- [GHSA-362c-34j8-85jq](https://github.com/meirka8/volute/security/advisories/GHSA-362c-34j8-85jq) (low): `cvc harness install claude-code` asks Git whether `.claude/settings.local.json` is ignored and otherwise declines the unattended copy into a new worktree, so a `.gitignore` negation cannot lead to the machine-specific hook settings being committed.

The release channels keep their existing protections, and the VS Code Marketplace gains one:

- Release tags must exactly match the Rust, VS Code extension, npm package, and Claude Code plugin versions before publishing, and are SSH-signed by the dedicated release identity documented in RELEASING.md (fingerprint published there for pin-verification).
- Release archives include a SHA-256 manifest; the installer and npm launcher verify the selected archive and reject unsafe redirects or archive members.
- The workflow pins its GitHub Actions by full immutable Git object SHA, uses scoped job permissions, and publishes GitHub build provenance attestations for workflow assets: `gh attestation verify <asset> --repo meirka8/volute`.
- npm publishing is configured to use npm trusted publishing, for both package names.
- VS Code Marketplace publishing is configured to use Visual Studio Marketplace Trusted Publishing: the release job exchanges a GitHub Actions OpenID Connect token for a Marketplace credential that lasts 15 minutes, and no Marketplace token is stored ([#180](https://github.com/meirka8/volute/issues/180)).
- The Claude Code plugin has no separate publish step: the marketplace entry pins its files to the release tag `v0.7.2`.

The same-release SHA-256 checksums are corruption/integrity checks, not independent signatures. Download only from this repository and review installers before running them.

## Known limitations

- **Linux ARM64 is not released.** The installers and npm launcher support the same platform matrix and reject unsupported platforms before downloading an asset.
- **The Claude Code transcript format is internal to Claude Code** and may change between its releases. The parser is pinned to transcript major version 2 and verified against fixtures shaped like the transcripts of Claude Code 2.1.219, 2.1.260, 2.1.289, and 2.1.300; another major version is refused whole, and an unfamiliar content block becomes a counted placeholder. Server-side tool outcomes are verified against a synthetic fixture, not a recorded session. Ingest reports the transcript version it refused.
- **Per-checkout hooks reach new worktrees only through Git's `post-checkout` hook.** Worktrees that already exist are not changed (run `cvc harness install claude-code` in each; it lists them). A `--no-checkout` worktree, one created by a client that does not run Git's hooks, one that already has a `.claude/settings.local.json`, and one where Git does not ignore that file get nothing. The plugin needs no per-worktree install. Cowork sessions, which run inside the desktop app's sandbox VM, are not supported.
- **Stopping Claude Code capture is per checkout.** `cvc harness uninstall claude-code` removes one checkout's hooks and stops new worktrees from getting them, but other worktrees keep theirs (the command lists them, and you run it in each). `/plugin disable cvc@volute` stops the plugin. Neither withdraws the capture acknowledgement, and a single command that stops capture everywhere is tracked in [#144](https://github.com/meirka8/volute/issues/144).
- **A very large transcript may not finish within a hook's 30 second budget.** A hook run commits nothing unless it finishes, so a transcript of roughly tens of megabytes on first ingestion (for example an old, long session resumed after installing the plugin) is not recorded by the hooks. Record it with `cvc ingest claude-code --transcript <file>` ([#149](https://github.com/meirka8/volute/issues/149)).
- **The Claude Code harness is verified on Linux and macOS only.** Windows binaries are released and the hook installer writes a Windows-quoted command, but hook execution on Windows has not been exercised, and the plugin's hooks are POSIX `sh` scripts that need Git Bash there; treat the Claude Code path as untested on Windows until a run is documented ([#97](https://github.com/meirka8/volute/issues/97)).
- **On Windows the conversations view only browses.** `s`, `u`, and `p` are disabled there and point to `cvc share`, `cvc unshare`, and `cvc push --manual`, because a typed phrase on Windows cannot yet discard keys typed ahead of the prompt. The VS Code share command keeps its two input boxes on Windows and with a `cvc` older than 0.7.1.
- **Advisory Git hooks call a bare `cvc`.** If `~/.cvc/bin` is not on the `PATH` Git's hook environment sees, post-commit time-window linking fails silently ([#92](https://github.com/meirka8/volute/issues/92)). The Claude Code in-session commit links use an absolute path and are unaffected.
- **Thoughts recorded through the MCP server link only as `temporal`**, because `commit_thought` carries no file context ([#23](https://github.com/meirka8/volute/issues/23)).
- **Transcript-derived commit links are recorded with the `generated` grade**; a distinct provenance grade for transcript evidence is a follow-up. Subagent conversations carry no recorded edge to the response that spawned them.
- `cvc privacy status` before `cvc init` still does not point at `cvc init` ([#93](https://github.com/meirka8/volute/issues/93)).
- **A byte-identical copy of a repository at the same path for the same user keeps its capture acknowledgement,** because the acknowledgement is bound to the checkout path and the user.
- **Conversations pulled by earlier versions keep ids that carry the old fingerprint.** Re-sharing one is the part of [GHSA-w2fm-2w52-vg5v](https://github.com/meirka8/volute/security/advisories/GHSA-w2fm-2w52-vg5v) that is deferred; the fix is planned for 0.8.
- **Sharing is explicit and per-conversation**, by design.
- **Hosted Reviewer requires deployment configuration.** The default Reviewer mode is local PAT mode.
