# Volute CVC v0.6.0

Volute CVC v0.6.0 makes the sharing workflow **discoverable**. Conversation ids — previously required by `cvc share` but displayed by nothing — now have a first-class listing, and a bare `cvc share` walks you through an interactive selection. The full flow from finished work to a populated Reviewer timeline is now: `cvc conversations` → `cvc share` → pick → type the challenge → `cvc push --manual`.

CVC keeps **explicitly available AI-assisted development context** alongside Git history. It records only information exposed or supplied by its integrations; it neither retrieves hidden chain-of-thought nor promises a verbatim record of a black-box model's internal reasoning.

[Full Changelog](https://github.com/meirka8/volute/compare/v0.5.0...v0.6.0)

## Highlights

- **`cvc conversations`** — a read-only listing of conversations, most recent activity first, with thought and linked-commit counts and, for the selected (or `origin`) remote, each conversation's share and publication state (`[private]` / `[shared, n/m published]`). It answers "what would I be sharing?" without touching any consent surface.
- **Interactive share picker.** A bare `cvc share` from a terminal lists the destination's unshared conversations and lets you pick one; the existing typed consent challenge then runs unchanged. The picker is gated on the same TTY check as the challenge, so no new non-interactive path exists — scripts must still name a conversation explicitly and are told so.
- **Legible consent.** `cvc share` now prints the conversation's title, thought count, and activity range before the challenge, so what you are consenting to is visible at the gate. The challenge phrase itself is unchanged.
- **Reviewer: projections with no squash/rewrite evidence now render.** The v5 format requires `events/` and `ranges/` trees, so an evidence-free repository correctly points them at Git's canonical empty tree — an object the GitHub API refuses to serve. The Reviewer no longer attempts to fetch that defined constant, fixing the silent empty Shadow Gallery for exactly the common case of a new repository's first published thoughts. (The Reviewer deploys continuously; this note is for completeness.)
- **Documentation:** Privacy.md opens with a plain-language "How your data moves" lifecycle (capture → link → share → push, and where the irreversibility boundary sits); RELEASING.md gains the release-signing preflight and key-compromise response.

## Included components

- `cvc-core` — Rust library for local storage, Git integration, policy enforcement, linking, and sync data structures.
- `cvc-cli` — the `cvc` command-line interface.
- `cvc-mcp` — MCP server for explicitly submitted interaction records and local history access.
- `cvc-lsp` — language server used by editor integrations.
- `cvc-plugin` — VS Code extension for the supported local VS Code chat-session workflow.
- `cvc-reviewer` — client-side React reviewer for GitHub-hosted CVC data.
- `@volute_cvc/cvc-mcp` — npm launcher for released CVC binaries.

## Install

### GitHub release assets

Once the full release workflow completes, download an archive and `SHA256SUMS.txt` from the [v0.6.0 GitHub release](https://github.com/meirka8/volute/releases/tag/v0.6.0). Verify the archive against that manifest **before** extracting it, then put `cvc` (or `cvc.exe`) on `PATH`. Each archive includes `cvc`, `cvc-mcp`, and `cvc-lsp`.

| Platform | Archive |
| --- | --- |
| Linux x86-64 | `cvc-x86_64-unknown-linux-gnu.tar.gz` |
| macOS x86-64 | `cvc-x86_64-apple-darwin.tar.gz` |
| macOS ARM64 | `cvc-aarch64-apple-darwin.tar.gz` |
| Windows x86-64 | `cvc-x86_64-pc-windows-msvc.zip` |

Expected additional release assets are `LICENSE`, `THIRD-PARTY-NOTICES.md`, `install.sh`, and `install.ps1`. Each native archive and VSIX also includes the mechanically generated third-party notice file. The standalone installer assets default to v0.6.0, select the matching supported archive, and verify its checksum; set `CVC_RELEASE_VERSION` to an explicit valid release tag to override that version. Review a script before running it.

From any Git working tree, get started with:

```bash
cvc init
cvc status
cvc conversations
```

### VS Code Marketplace

After the full release workflow completes, [Volute CVC (`volute.cvc`)](https://marketplace.visualstudio.com/items?itemName=volute.cvc) is expected to be available from the VS Code Marketplace. The extension supports VS Code `^1.91.0` and uses the platform-specific bundled language server.

### npm MCP launcher

After the full release workflow completes, the [@volute_cvc/cvc-mcp](https://www.npmjs.com/package/@volute_cvc/cvc-mcp) launcher is expected to be available from npm:

```bash
npm install --global @volute_cvc/cvc-mcp@0.6.0
```

It provides `cvc-mcp` and `cvc`, downloads the matching release binary on first use, and verifies it against the release checksum manifest. Configure `cvc-mcp` in your MCP client as documented in the [MCP setup guide](https://github.com/meirka8/volute/blob/v0.6.0/cvc-mcp/README.md).

## Upgrade notes

- **No database migration and no wire-format change.** The new listing is a read-only query; sync output remains byte-compatible v5, and v0.5.x binaries interoperate freely.
- Dependency refresh across the workspace, including git2 0.19 → 0.20.4 (libgit2 1.9.x). No behavior changes.
- Consent semantics are unchanged everywhere: same challenges, same per-destination boundaries, same inert bare `cvc push` without a standing auto-push grant.

## Privacy and sharing

CVC is **local-first, not local-only**. Captures live under the repository's common Git directory in `cvc/` and are private by default; linked worktrees share that private store. Remote publication is a separate, explicit action behind per-destination consent and an interactive challenge. See Privacy.md's new "How your data moves" section for the full lifecycle in plain language.

Review content before sharing and protect access to the repository and its common Git directory. Built-in scrubbing and `.thoughtignore` are defense in depth, not a guarantee. Once published to Git, content may remain in objects, clones, forks, reflogs, caches, and backups. Rotate an exposed credential first; local deletion and tombstones are suppression mechanisms, not guaranteed physical erasure.

## Release security and hardening

- Release tags must exactly match the Rust, VS Code extension, and npm package versions before publishing, and are SSH-signed by the dedicated release identity documented in RELEASING.md (fingerprint published there for pin-verification).
- Release archives include a SHA-256 manifest; the installer and npm launcher verify the selected archive and reject unsafe redirects or archive members.
- The workflow pins its GitHub Actions by full immutable Git object SHA, uses scoped job permissions, and publishes GitHub build provenance attestations for workflow assets: `gh attestation verify <asset> --repo meirka8/volute`.
- npm publishing is configured to use npm trusted publishing.

The same-release SHA-256 checksums are corruption/integrity checks, not independent signatures. Download only from this repository and review installers before running them.

## Known limitations

- **Linux ARM64 is not released.** The installers and npm launcher support the same platform matrix and reject unsupported platforms before downloading an asset.
- **Sharing is explicit and per-conversation** — by design; the new picker cheapens the act, never the deliberation.
- **The VS Code extension's Share command still asks for a conversation id by text input**; a picker over the same summary data is a tracked follow-up ([#65](https://github.com/meirka8/volute/issues/65) covers the CLI; the extension part is noted there).
- **Exact squash relinking expects a range to be observed from one worktree** ([#39](https://github.com/meirka8/volute/issues/39)); affected thoughts stay floating rather than mislinked.
- **Very high concurrent capture volume can hit database lock contention** ([#40](https://github.com/meirka8/volute/issues/40)).
- **Hosted Reviewer requires deployment configuration.** The default Reviewer mode is local PAT mode.
